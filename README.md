# 让 AI 讲懂一条流程

一套可以交给 AI 的讲解方法，帮助你理解自己不熟悉的操作流程、工作流程或技术管线。

## Motivation

遇到一个不熟悉的流程时，我们常常只想尽快弄明白：从哪里开始，经过哪些步骤，每一步由谁做了什么，最后得到什么。AI 可以解释术语，却不一定会把这些步骤串起来；如果每次都要反复说明自己的基础、要求它举例、追问步骤之间怎样衔接，理解的成本仍然很高。

这个项目把讲解时有效的经验整理成一套可复用的方法：从读者已有的知识出发，选一个具体任务，沿真实流程解释参与者、动作和交接；需要深入时回到对应节点补充。目标是让 AI 更快给出能跟着走、能继续追问的讲解，帮助读者真正理解整个过程。

## 快速开始

把本仓库的 [结构与阅读组织](structure.md) 和 [语言与表达](language.md) 提供给 AI，然后给出你想理解的流程和现有材料。可以从下面的请求开始：

```text
请按照提供的《结构与阅读组织》和《语言与表达》讲解这个流程：

我想理解：[流程或操作]
我已经了解：[已有知识；不确定可以留空]
我想弄明白：[例如从输入到结果、某个步骤怎么做、各环节如何交接]
可用材料：[文档、代码、截图或链接]

请选一个具体例子贯穿讲解，先给出主线，再逐步说明谁拿到什么、做了什么、结果怎样进入下一步。遇到材料不足的地方标明尚不清楚；如果缺少的信息影响理解，请简短询问。最后让我有机会用自己的话串讲，并根据我的追问补充对应节点。
```

如果 AI 能读取仓库，也可以直接让它先阅读这两份文档，再结合你的问题讲解。讲解中可以随时指出哪里没跟上，要求它换一个例子或展开某个节点。

## 方法内容

| 文档 | 解决的问题 |
| --- | --- |
| [结构与阅读组织](structure.md) | 确定知识基础和主管线，用具体例子串起步骤，组织图、补充内容与理解反馈。 |
| [语言与表达](language.md) | 清楚说明动作和数据交接，把类比、术语与代码放回具体任务，并区分事实和示意。 |

适合讲解实际操作、工作流程、程序运行过程和计算过程。具体呈现形式可以是对话、文档或带节点导航的图解，由内容和阅读需求决定。

## 已知边界

讲解质量取决于可获得的材料和 AI 对材料的理解。涉及真实系统时，应结合文档、代码或实际运行证据核实关键步骤；缺少证据的内部细节需要保持为未知。仓库提供讲解方法，不包含自动运行流程的软件。
